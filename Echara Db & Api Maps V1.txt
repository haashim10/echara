2) Key Indexes & Query Notes
Listings
category: 1 , location.lat: 1 , location.lng: 1  (or 2dsphere index on location
for geo queries)
Text index on description  and tags
Bookings
vendorId: 1, status: 1, requestedSlot.startISO: 1
Unique guard against overlapping confirmed  slots per vendor/listing
Chats
buyerId: 1, vendorId: 1, lastMessageAt: -1
Reviews
vendorId: 1, createdAt: -1
AdminLogs
createdAt: -1 , action: 1 , targetType: 1

4) Sequence Diagrams (Key Flows)
4.1 Booking Request (No In-App Payment)
sequenceDiagram
  autonumber
  participant Buyer
  participant WebAPI as Echara API
  participant Vendor
  participant Notif as Notifications
  participant DB as MongoDB
  Buyer->>WebAPI: GET /listings/search (filters)
  WebAPI->>DB: Query listings (indexes)
  DB-->>WebAPI: Results
  WebAPI-->>Buyer: Listings
  Buyer->>WebAPI: POST /bookings (listingId, slot)
  WebAPI->>DB: Create booking{status: pending}
  DB-->>WebAPI: _id
  WebAPI->>Notif: Push + Email to Vendor (pending)
  Notif-->>Vendor: New booking request
  Vendor->>WebAPI: POST /bookings/:id/approve
  WebAPI->>DB: Update status→confirmed + approvedAt
  DB-->>WebAPI: OK
  WebAPI->>Notif: Push to Buyer (confirmed)
  Notif-->>Buyer: Booking confirmed
  Note over Vendor,WebAPI: Vendor may later POST /bookings/:id/payment-log
4.2 Realtime Chat Setup
sequenceDiagram
  autonumber

  Socket->>DB: Persist message
  Socket-->>Client: echo (sender)
  Socket-->>Others: broadcast to other participant
5) Error Model & HTTP Status Conventions
2xx success; 400 validation; 401 unauthenticated; 403 unauthorized; 404 not found; 409 conflict
(e.g., overlapping booking); 429 rate-limited; 500 server error .
All error payloads return { code, message, details? } .
